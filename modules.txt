### Purpose

Admin can quickly see the business summary of the travel agency.

### Features

* Show total bookings.
* Show total revenue.
* Show total active packages.
* Show pending inquiries.
* Show recent bookings.
* Show popular destinations.
* Show booking status summary: Pending, Confirmed, Cancelled, Completed.

* 4 summary cards.
* Recent booking list.
* Mock revenue chart or simple stat section.

# 7-Person Implementation Handoff

Use this section for the actual team split. The current project is a React 19 + Vite + Tailwind frontend. It does not use React Router yet. The dashboard is controlled by tab state inside `src/app/App.tsx`, and the sidebar tab type lives in `src/components/layout/Sidebar.tsx`.

Current important files:

* `src/app/App.tsx` - owns active tab, fetches mock data, filters lists, renders each screen.
* `src/components/layout/Sidebar.tsx` - owns `SidebarTab` union and menu items.
* `src/components/layout/DashboardLayout.tsx` - wraps sidebar, header, mobile menu, page scroll.
* `src/types/travel.ts` - shared TypeScript types.
* `src/services/travelApi.ts` - fake async API over in-memory mock data.
* `src/data/*` - mock datasets.
* `src/components/common/*` - reusable search, empty, loading UI.

Global rules for everyone:

* Mock data only. No paid API. No backend dependency.
* Use Tailwind classes already used in the app.
* Use `lucide-react` icons only.
* Keep components typed with interfaces from `src/types/travel.ts`.
* Keep code client-side and demo-ready.
* Do not delete or rename other people's files.
* Run `npm run build` before submitting.
* If touching `App.tsx` or `Sidebar.tsx`, coordinate first because those files will conflict.

Recommended merge order:

1. Module 1 first because it prepares common layout, tabs, and shared contracts.
2. Modules 2 to 7 can then work mostly in their own component/data files.
3. One person should do final integration in `App.tsx` after all module components exist.
